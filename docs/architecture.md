# Architecture

Swift 5.9 package, macOS 14 and iOS 17, no third-party dependencies, XCTest. One engine (`InkRelayCore`) is used by every front end.

## Targets

| Target | Where | What |
|---|---|---|
| `InkRelayCore` | `Sources/InkRelayCore` | The library: config, sources, recognition, destinations, the engine, review stack, MCP |
| `inkrelay` | `Sources/inkrelay/main.swift` | The command-line tool; every command is a `case` in one switch |
| `InkRelayBar` | `Sources/InkRelayBar` | The menu bar app (SwiftUI `MenuBarExtra` plus AppKit windows); `scripts/build-app.sh` bundles it with the CLI inside |
| iOS app | `iOS/` | iPhone and iPad app, generated by XcodeGen from `iOS/project.yml`; `scripts/build-ios.sh` builds it |

## A sync pass

`RelayEngine.syncOnce()` is the whole product. It takes a file lock (`.sync.lock` beside the state), reloads state from disk, then:

1. **Pulls cloud sources into local folders.**
   - `ViwoodsCloudPuller` mirrors notebooks, memos and planner days as PDFs into `viwoods/` and sends typed planner to-dos straight to plan destinations.
   - `KindleMailPuller` saves Kindle Scribe notebook emails from Mail into `kindle/`.
2. **Scans every source folder** (`FolderScanner`). Each file is skipped when its size and date match the record. Otherwise it's hashed: same hash means touched but unchanged, and a hash matching a missing file means a rename or move.
3. **Recognizes** changed exports with `VisionTextRecognizer`, or `ClaudeTextRecognizer` for sources set to `"recognizer": "claude"`, which falls back to Vision. Supernote `.note` files are first converted to PDF (`ExportConverter`).
4. **Builds an `InkNote`** (title from the file name, pages with text) and archives its text in `NoteArchive` for search.
5. **Delivers** it to each destination still behind for that content hash. A failure only retries that destination.
6. **Handles exports that disappeared:** renames move notes, and `onDelete` policies (`keep`, `archive`, `delete`) decide the rest. A source folder that is suddenly empty never deletes anything.
7. **Publishes the review stack for phones** when `reviewStack.shareWithPhone` is on, after applying the phones' decisions (`ReviewPublisher`).

Who runs passes:
- `inkrelay sync`: one pass.
- `inkrelay watch`: FSEvents on source folders plus a rescan timer.
- The menu bar app: `RelayRunner`, same triggers, on its own queue, publishing `Snapshot`s for the menu.
- The MCP server's `inkrelay_sync_now` tool.

The lock keeps them from overlapping.

## Sources

- **Folder sources** (`sources`): any folder a tablet exports to (Google Drive, Dropbox, OneDrive, iCloud Drive). File types per source.
- **Viwoods Cloud** (`viwoodsCloud`): see [viwoods-cloud.md](viwoods-cloud.md). Its cache folder is an implicit source.
- **Kindle Scribe** (`kindleMail`): notebooks shared by email, picked up from Mail with AppleScript.
- **Supernote:** `.note` files in a folder source, decoded natively ([supernote-format.md](supernote-format.md)).

## Destinations

Each one is a `NoteDestination` (`upsert(note, previous:)` returning an external id; optional `remove`). Planner sinks are also `PlanDestination`s.

| Kind | How |
|---|---|
| `obsidian` | Markdown plus the original PDF in the vault; only the text between `%% inkrelay:start %%` and `%% inkrelay:end %%`, and its own frontmatter keys, are rewritten |
| `appleNotes` | AppleScript through `osascript`; original attached |
| `appleCalendar` | AppleScript; planner day pages and typed to-dos as all-day events |
| `appleReminders` | AppleScript; written tasks (`☐`, `[ ]`, `TODO`) from `TaskExtractor` |
| `googleCalendar`, `googleDocs` | REST; loopback OAuth with PKCE, scopes `calendar.app.created` and `drive.file` |
| `outlookCalendar`, `oneNote` | Microsoft Graph; device-code sign-in, `Calendars.ReadWrite`, `Notes.ReadWrite`, `offline_access` |
| `notion` | REST; integration token in the Keychain |
| `reviewStack` | Cards in `review/`; web page on 127.0.0.1:7788; optional sharing to phones |

All the calendar destinations build their events from `PlannerEvent`, so titles and text match everywhere. `TimedEventWriter` is what the review stack calls to add a suggested event.

## Review stack

- `ReviewStackDestination` turns each non-blank page into a card (page image as JPEG plus text). Dated lines become suggested-event cards. Typed to-dos become to-do cards.
- `ReviewStore` keeps `review/stack.json` and `review/images/`, behind a file lock.
- `ReviewServer` serves the card page (`ReviewPage.html`), on the loopback interface only, with a Host check and an `X-InkRelay` header for actions.
- `ReviewMirror.swift` shares the stack with phones (`ReviewPublisher` on the Mac, `PhoneReviewStack` on the phone):
  - The Mac writes `Review/stack.json` and `Review/images/` in the shared folder.
  - Each phone writes only `Review/decisions-<device>.json`.
  - The Mac applies decisions on its next pass and remembers their ids in `review/applied.json` for 60 days.

## Other pieces

- **Send to tablet** (`Send/`): an article URL or document becomes an EPUB (hand-written zip in `ZipWriter`) or PDF, then sent by `sendTargets` kind: `folder`, `kindle` (email) or `viwoodsCloud` (uploaded into Learning or Paper).
- **MCP server** (`MCP/`): newline-delimited JSON-RPC 2.0 over stdio, protocol `2025-11-25` (also accepts `2025-06-18`, `2025-03-26`, `2024-11-05`). Nine tools, each prefixed `inkrelay_`:
  - `status`;
  - `list_notes`, `search_notes` and `get_note`, read from the archive;
  - `list_tasks`;
  - `review_stack` and `review_card`;
  - `sync_now`;
  - `send_to_tablet`.
- **Shared ledger** (`SharedLedger`): `ledger.json` in iCloud Drive/InkRelay, listing what any device filed into Apple Notes, so the Mac and phone don't both file it. It merges iCloud conflict copies.
- **Setup and doctor** (`Setup/`): `SetupChoices` turns the setup answers into a config. `Doctor` checks folders, permissions, sign-ins and the agent. `NotesRoundTrip` exercises real Notes.
- **iOS app:** reads an export folder through a security-scoped bookmark and recognizes on device. It hands notes to Shortcuts, because Apple Notes has no API, and shows the shared review stack.

## Files on disk

`~/Library/Application Support/InkRelay/` (with `--config`, the folder holding that config):

| Path | What |
|---|---|
| `config.json` | The config (`RelayConfig`) |
| `state.json` | One `FileRecord` per export: size, date, hash, per-destination records, `missingSince`, `blank` |
| `.sync.lock` | One pass at a time across processes |
| `viwoods/` | Viwoods Cloud cache (PDFs) and `.manifest.json` |
| `viwoods-token.json` | Viwoods token, refreshed automatically |
| `google-token.json`, `microsoft-token.json`, `google-ids.json` | OAuth tokens (owner-only files) and created calendar or folder ids |
| `kindle/` | Saved Kindle notebooks and `.handled.json` |
| `archive/` | Recognized text of every note, for search and MCP |
| `converted/` | PDFs made from Supernote `.note` files |
| `review/` | `stack.json`, `images/`, `.lock`, `applied.json` |
| `ai-usage.json` | This month's AI transcription spend |

The Notion token and Anthropic API key are in the Keychain under the service "InkRelay". Logs from the launch agent and the app are in `~/Library/Logs/InkRelay`.

Shared with phones, in iCloud Drive/InkRelay (`~/Library/Mobile Documents/com~apple~CloudDocs/InkRelay`): `ledger.json` and `Review/`.
